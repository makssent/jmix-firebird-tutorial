= Firebird Limitations

This section summarizes known limitations and considerations for using Firebird with Jmix that were identified in practice.

[[unofficial-support]]
== Support Through an Add-on

Firebird is supported in Jmix through the https://www.jmix.io/marketplace/firebird-db/[Firebird add-on in Jmix Marketplace^]. The add-on enables applications to use Firebird as their primary database.

The `jmix-firebird-addon` is maintained separately from the core Jmix platform.

[[changelog-generation]]
== Automatic Liquibase Changelog Generation

For DBMSs supported by Jmix out of the box, Studio compares the data model with the database schema before startup and can automatically generate a Liquibase changelog for missing objects. This mechanism is unavailable for Firebird: Studio does not create changesets for data model changes or provide a ready-to-use schema update.

Therefore, when adding an entity, attribute, reference, index, or another object, the developer must determine the required database changes, describe them in an XML changelog, and select appropriate types and change types with Firebird in mind. This is the main practical blocker because every data model change requires the corresponding schema change to be prepared and verified manually.

This limitation applies only to automatic generation. Manually created changelogs are executed normally by Liquibase when the application starts, so a prepared migration can be applied in the same way as for other DBMSs.

[TIP]
====
For an example of creating a Liquibase changelog, see the xref:tutorial:data-in-ui.adoc#joining-date-attr[tutorial section on adding the joiningDate attribute]. It explains how to create a changelog with one changeset and describes the resulting changes.

The process of creating a Liquibase changelog is described in more detail in xref:liquibase-changelog.adoc[Creating a Liquibase Changelog].
====

[[third-party-support]]
== Firebird Support in Third-Party Libraries

Jmix uses Liquibase and EclipseLink for database operations. Liquibase manages the database schema and applies changelogs, while EclipseLink provides application-level database access.

Both libraries already support Firebird. However, some of that support was implemented for older Firebird versions, so certain restrictions and checks may no longer apply to current DBMS versions.

[[sequence-start-value]]
=== Example: createSequence and startValue

When creating a sequence, Liquibase prohibited the `startValue` attribute for Firebird regardless of the database version. The following changeset:

[source,xml]
----
<createSequence sequenceName="CRM_PAYMENT_NUMBER" startValue="1000"/>
----

failed with the following error:

[source]
----
startValue is not allowed on firebird
----

This restriction no longer applies to Firebird 4.0 and later. It comes from Liquibase's Firebird implementation rather than Jmix, so the appropriate fix belongs in Liquibase itself.

To run the project, `jmix-crm-firebird` uses a temporary workaround: the regular changeset excludes Firebird, while a separate Firebird changeset creates the sequence without `startValue` and then sets the initial value with an SQL statement:

[source,xml]
----
<changeSet id="1" author="crm" dbms="!firebird">
    <createSequence sequenceName="CRM_PAYMENT_NUMBER" startValue="1000"/>
</changeSet>

<changeSet id="2" author="crm" dbms="firebird">
    <createSequence sequenceName="CRM_PAYMENT_NUMBER"/>
    <sql>ALTER SEQUENCE CRM_PAYMENT_NUMBER RESTART WITH 1000</sql>
</changeSet>
----

See the complete example in this https://github.com/makssent/jmix-crm-firebird/commit/724d0a46f18aa9188a7e847e03fedf2fb74456f9[jmix-crm-firebird commit^].

A fix for correct `startValue` behavior was submitted directly to Liquibase: https://github.com/liquibase/liquibase/pull/7922[PR #7922^].

== Conclusion

This page lists the limitations currently known. No additional limitations were found while completing the tutorial, running the real-world `jmix-crm` application, and executing its tests. Further use of Firebird with Jmix may reveal other considerations.
