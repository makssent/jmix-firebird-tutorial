= 1. Project Setup

In this chapter you will go through a few simple steps to set up a new project. You will learn how to navigate the project structure and locate essential components. Once your project is set up, you will be able to run it and explore its pre-built features.

[[dev-env]]
== Setting Up Development Environment

Install Jmix Studio and JDK as described in the https://docs.jmix.io/jmix/setup.html[Setup^] section of the Jmix documentation if you haven't done it yet.

In this tutorial, we will use some premium Studio features such as visual designers and code generation capabilities. These features are available for free in small projects containing up to 10 entities and roles, such as the tutorial project.

When you run Jmix Studio for the first time, you should log in to the Jmix account, and after that a trial subscription for 28 days is activated. The subscription allows you to use the premium features in projects of any size. After the trial subscription expires, Studio will continue working without subscription, providing premium features only for small projects.

[[create-project]]
== Creating Project

Run IntelliJ IDEA with Jmix Studio plugin installed, switch to the *Projects* tab and click *New Project*:

image::project-setup/create-project-1.png[align="center",width="912"]

On the first step of the *New Project* wizard, select *Jmix Project* in the list and leave default values in the *Repository* and *Jmix version* fields:

image::project-setup/create-project-2.png[align="center",width="914"]

In the *Project JDK* field, select a JDK version 17 or 21. If the field displays `<No SDK>`, select *Download JDK* in its dropdown list and follow further instructions to download and select a JDK.

Click *Next*.

On the next step of the *New Project* wizard, select the first project template from the list: `Full-Stack Application (Java)`:

image::project-setup/create-project-3.png[align="center",width="915"]

Click *Next*.

On the last step of the *New Project* wizard, enter `onboarding` to the *Project name* field:

image::project-setup/create-project-4.png[align="center",width="915"]

The *Base package* field defines the Java package which will contain all classes and resources of the project. Keep the value suggested by the wizard (`com.company.onboarding`) to conform the code in the tutorial.

*Project id* is optional for an application, so leave the field empty.

Click *Create*.

NOTE: After the project is created, IDE starts downloading dependencies and indexing the project. On the first launch, it may take significant time (up to 10 minutes or more, depending on your internet connection and computer power). Please wait until the progress indicator in the status bar disappears.

[TIP]
====
The IDE will show a number of notifications suggesting to download "pre-built shared indexes" and install additional plugins. You can safely refuse them.
====

[[add-firebird]]
== Preparing to Run

The created project is configured to use the embedded HSQLDB database. Before running it, switch the project to Firebird: add the add-on and driver, specify the connection parameters, and adjust the Liquibase changelogs.

[[firebird-dependencies]]
=== Dependencies

Open `build.gradle`. In the `dependencies` block, add the add-on and the Firebird driver:

[source,groovy]
----
dependencies {
    implementation 'io.jmix.core:jmix-core-starter'
    implementation 'io.jmix.data:jmix-eclipselink-starter'
    implementation 'io.jmix.security:jmix-security-starter'
    implementation 'io.jmix.security:jmix-security-flowui-starter'
    implementation 'io.jmix.security:jmix-security-data-starter'
    implementation 'io.jmix.localfs:jmix-localfs-starter'
    implementation 'io.jmix.flowui:jmix-flowui-starter'
    implementation 'io.jmix.flowui:jmix-flowui-data-starter'
    implementation 'io.jmix.flowui:jmix-flowui-themes'
    implementation 'io.jmix.datatools:jmix-datatools-starter'
    implementation 'io.jmix.datatools:jmix-datatools-flowui-starter'

    // Added for Firebird: the add-on that provides database support
    implementation 'io.github.makssent:jmix-firebird-starter:3.0.1'

    implementation 'org.springframework.boot:spring-boot-starter-web'
    implementation 'com.vaadin:vaadin-dev'

    runtimeOnly 'org.hsqldb:hsqldb'
    // Added for Firebird: JDBC driver
    runtimeOnly 'org.firebirdsql.jdbc:jaybird:6.0.5'

    testImplementation('org.springframework.boot:spring-boot-starter-test') {
        exclude group: 'org.junit.vintage', module: 'junit-vintage-engine'
    }
    testImplementation 'io.jmix.flowui:jmix-flowui-test-assist'
}
----

The `jmix-firebird-starter` add-on enables the platform to work with Firebird. It implements the Jmix interfaces that describe the database dialect, registers an EclipseLink platform with the correct mapping of Java types to Firebird types, and adds a Liquibase changelog containing property values referenced by the platform's own scripts. You can learn more about the add-on on the https://www.jmix.io/marketplace/firebird-db/[Firebird page in Jmix Marketplace^]. Jaybird is the open-source https://github.com/FirebirdSQL/jaybird[FirebirdSQL/jaybird^] JDBC driver for Firebird.

[NOTE]
====
After editing `build.gradle`, the IDE will prompt you to update the project. Click *Load Gradle Changes* or *Reload All Gradle Projects* (image:common/refresh.svg[]) in the *Gradle* tool window; otherwise, the new dependencies will not be added to the classpath.
====

[[firebird-connection]]
=== Connection Parameters

In `application.properties`, replace the HSQLDB parameters with the parameters of your Firebird database:

[source,properties]
----
# Replaced: connect to Firebird instead of HSQLDB
#main.datasource.url=jdbc:hsqldb:file:.jmix/hsqldb/onboarding
#main.datasource.username=sa
#main.datasource.password=
main.datasource.url=jdbc:firebird://localhost:3050//path/to/onboarding.fdb?encoding=UTF8
main.datasource.username=sysdba
main.datasource.password=masterkey

# Added for Firebird
main.datasource.driver-class-name=org.firebirdsql.jdbc.FBDriver
jmix.data.dbms-type=firebird
----

The `jmix.data.dbms-type` property is essential: the platform uses it to select the implementations provided by the add-on. Without it, Jmix will not recognize Firebird even if the driver is present.

[WARNING]
====
The database must exist before the first run. Unlike embedded HSQLDB, Firebird does not create the database file automatically. Create an empty database in advance, for example with the `isql` utility, and specify its path in `main.datasource.url`. Liquibase will create the tables when the application starts.
====

[[firebird-liquibase]]
=== Liquibase Changelogs

Two changes to the changelogs are still required.

First, open the master changelog. In the *Jmix* tool window, it is located under *Data Stores* -> *Main Data Store* -> *Liquibase: changelog.xml*. Alternatively, open `src/main/resources/com/company/onboarding/liquibase/changelog.xml` in the project tree. Add the add-on changelog before the Jmix module changelogs:

[source,xml]
----
<?xml version="1.0" encoding="UTF-8"?>
<databaseChangeLog
        xmlns="http://www.liquibase.org/xml/ns/dbchangelog"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://www.liquibase.org/xml/ns/dbchangelog
                      http://www.liquibase.org/xml/ns/dbchangelog/dbchangelog-latest.xsd">

    <!-- DO NOT REMOVE. This is a master changelog that runs all other changelogs. -->

    <!-- Added for Firebird: must precede the Jmix module changelogs -->
    <include file="/io/github/makssent/jmix/firebird/liquibase/changelog.xml"/>

    <include file="/io/jmix/data/liquibase/changelog.xml"/>
    <include file="/io/jmix/flowuidata/liquibase/changelog.xml"/>
    <include file="/io/jmix/securitydata/liquibase/changelog.xml"/>

    <includeAll path="/com/company/onboarding/liquibase/changelog"/>

</databaseChangeLog>
----

The order is important. A declared property is visible only to scripts included below it, so the add-on changelog must come first.

Second, open the nested `010-init-user.xml` file, which creates the administrator account. In the project template, these inserts are restricted to a list of DBMS types that does not include Firebird. Add `firebird` to the `dbms` attribute of both changesets:

[source,xml]
----
<insert tableName="USER_" dbms="postgresql, mssql, hsqldb, firebird">
----

[source,xml]
----
<insert tableName="SEC_ROLE_ASSIGNMENT" dbms="postgresql, mssql, hsqldb, firebird">
----

Without this change, the database will be initialized without the `admin` account, and you will not be able to log in.

[[run-app]]
== Running the Application

You can run the new project right after opening it in the IDE and see the initial state of your application.

[WARNING]
====
The original Jmix tutorial starts the application with the *Debug* button (image:common/start-debugger.svg[]) in the main toolbar. This method does not work with Firebird.

Before starting, Studio compares the data model with the database schema and generates a migration script if they differ. To do this, Studio must be able to recreate the database, but this support is implemented only for the DBMSs supported by Jmix out of the box: HSQLDB, PostgreSQL, MySQL, MariaDB, Microsoft SQL Server, and Oracle. Firebird is not on this list, so the check fails before the application starts.
====

Run the application from the command line instead. Open a terminal in the project root and execute:

[source,bash]
----
./gradlew bootRun
----

When the application starts, Liquibase executes all project changelogs: first the scripts from Jmix dependencies, and then the project's own scripts (`010-init-user.xml`). This creates the tables and the administrator account in the empty database.

When the application is ready, the following messages appear at the end of the console output:

[source]
----
Application started at http://localhost:8080
Application running at http://localhost:8080/
----

[[enter-app]]
=== Entering Application

Open `localhost:8080` in a web browser. You will see your application login view:

image::project-setup/run-app-5.png[align="center"]

The `admin` / `admin` credentials are already set in the username and password fields (you can remove them later), so just click *Log in*.

In the main menu, click *Application* -> *Users*:

image::project-setup/run-app-6.png[align="center"]

It's the `Users.list` view showing the list of `User`  entities. Now it has only the `admin` user created in the database by the `010-init-user.xml` changelog.

[[stop-app]]
=== Stopping the Application

To stop the running application, press `Ctrl+C` in the terminal.

[[summary]]
== Summary

In this section, you have set up the development environment and created a new project in the IDE.

You have learned that:

* Jmix Studio is a plugin for IntelliJ IDEA.
* The tutorial assumes that you have a commercial or trial {jmix-docs}/studio/subscription.html[subscription^] for Jmix Studio. A trial subscription is issued when logging in to Jmix account for the first time.
* Studio has a wizard for creating new projects by templates.
* Studio shows the project structure in the *Jmix* tool window.
* The new project contains functionality for logging in to the application and managing users.
* With Firebird, the application must be started from the command line because Studio cannot perform its pre-run database schema check.
* The Firebird database must be created in advance; Liquibase initializes its schema when the application starts.
